How we decide what to build

1. User votes. The vote counts on this page are real. Features with more votes get prioritized. This isn't performative — it's how I actually plan sprints.

2. Core completeness. I prioritize finishing existing modules over starting new ones. Half-built features help nobody.

3. My own use. I use WorkGrid daily. If something annoys me, I fix it. Dogfooding catches issues feedback can't.

4. Effort vs. impact. A feature that takes 2 days and helps 80% of users ships before a feature that takes 2 weeks and helps 10%.
